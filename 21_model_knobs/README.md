# 21_model_knobs —— 把文章里的机制找回它们在模型上的旋钮

前面 `20_runtime_probe` 只回答一个问题：一次真实推理占几颗核。这一组回答另一个：
文章前 15 节讲的机制，在 llama.cpp 上到底有没有对应的旋钮？拧了以后量级对不对得上？

## 旋钮对照

| 机制 | 旋钮 | 说明 |
|---|---|---|
| 并行扩展 | `-t 1..4` | 线程数 |
| 批大小 | `-b 1 / 16 / 64 / 256 / 512` | 预填充时一次喂多少 token |
| KV cache | `-d 0 / 1024 / 4096` | 解码前先填多深的 KV |
| 量化 | 换 gguf | q2_k / q4_k_m / q8_0 |
| 超订 | `-t 8 / 16` | 4 核上开 8、16 线程 |
| 绑核 | `taskset -c 0-3` | 与不绑对比 |
| 权重加载 | `-lm mmap / none` | 映射读 vs 读进堆 |
| 线程占用 | `perf stat -e task-clock` | 每 token CPU ÷ 每 token 墙钟 |

## 方法

每个用例跑 `-r 4` 与 `-r 1` 各一次，CPU 时间取 `perf stat -e task-clock`
（内核在上下文切换时累加，不受轮询漏计影响），相减除以 3 得到单次计算成本：

```
单次 CPU = (task-clock(r=4) − task-clock(r=1)) ÷ 3
```

线程扩展那 8 个用例跑了三轮（`run_threads_rep.sh` 后缀 r2 / r3），每配置取三轮最小值，
因为这台虚拟机同一配置的极差有 15%。

## 主要结果（q4_k_m，4 vCPU）

| 用例 | 每 token CPU | 每 token 墙钟 | 占核 | 吞吐 |
|---|---:|---:|---:|---:|
| 预填充 / 1 线程 | 19.60 ms | 19.72 ms | 0.99 | 50.7 t/s |
| 预填充 / 2 线程 | 18.46 ms | 9.58 ms | 1.93 | 104.4 t/s |
| 预填充 / 3 线程 | 19.54 ms | 6.72 ms | 2.91 | 148.8 t/s |
| 预填充 / 4 线程 | 22.49 ms | 7.13 ms | 3.15 | 140.2 t/s |
| 解码 / 1 线程 | 54.84 ms | 55.25 ms | 0.99 | 18.1 t/s |
| 解码 / 2 线程 | 58.40 ms | 29.24 ms | 2.00 | 34.2 t/s |
| 解码 / 3 线程 | 65.89 ms | 22.32 ms | 2.95 | 44.8 t/s |
| 解码 / 4 线程 | 93.83 ms | 25.00 ms | 3.75 | 40.0 t/s |

**4 线程是坏档位**：解码 3→4 线程吞吐 44.8 → 40.0（−11%），每 token CPU 65.9 → 93.8 ms（+42%）。
`perf record -s dso` 给出了原因：libgomp 的等待占比 13.66% → 28.64%，内核时间 0.71% → 3.63%。

其余旋钮（单轮，量级远超 15% 噪声）：

- 批大小 `-b`：每 token CPU 100.0 → 22.2 ms（4.5×），吞吐 37.2 → 133.2 t/s
- KV 深度 `-d`：110.2 → 141.1 → 226.1 ms，深度 0→4096 翻 2.05 倍，线性
- 量化：q2 78.1 / q4 95.9 / q8 119.7 ms，吞吐 48.7 / 38.5 / 31.6 t/s
- 超订：8 线程 9.1 t/s、每 token 65.1 万次切换；16 线程 5.6 t/s、136.6 万次
- 绑核：4 线程绑 0-3 为 95.5 ms，与不绑 93.8 ms 在噪声内
- 加载方式：mmap 116.6 ms、read 116.3 ms，整进程缺页 10938 / 10959，速度无差

## 测不了的

缓存层级、分支预测、指令级并行、假共享、大小核、进程/线程、mmap 的回收收益，这七项在
真模型上没有旋钮：这台虚拟机未暴露 vPMU（`perf stat -e cycles` 返回 `<not supported>`），
`cache-miss` / `branch-misses` 都采不到；量化点积的展开方式写在 ggml 里，应用层改不了。

## 复现

```bash
bash run_knobs.sh                  # 全量旋钮，约 17 分钟
bash run_threads_rep.sh r2         # 线程扩展再跑一轮，用于取最小值
bash prof_threads.sh               # 3 线程与 4 线程各采一次样
python3 analyze.py                 # 差分表
```

依赖：llama.cpp（`BIN` 可覆盖）、q4_k_m / q2_k / q8_0 三个 gguf、`perf`、`taskset`。
