# CPU 计算热点与内存瓶颈定位 —— 实验报告

被测对象：大模型推理的两条流水线——decode 的 GEMV（带宽受限）与 prefill 的 GEMM（算力受限）。
测量时间：2026-11-22。所有原始输出见 `results/`。

---

## 一、环境能力清单

| 项目 | 内容 |
|---|---|
| 内核 | Linux 6.8.0-149-generic（Ubuntu 24.04.5 LTS） |
| 处理器 | Intel Core i5-7300HQ @ 2.50 GHz，4 vCPU |
| 缓存 | L1 32 KB/核，L2 256 KB/核，L3 6 MB（共享）—— 规格值 |
| 指令集 | AVX2 / FMA3 |
| 编译器 | gcc 13.3.0（`-O2 -mavx2 -mfma`） |

**读不到的接口**

| 接口 | 结果 |
|---|---|
| `perf stat -e cycles,instructions` | `<not supported>`（`perf_event_paranoid=4`） |
| `perf stat -e cache-misses` | 同上 |
| `cpufreq`（当前频率） | 目录不存在 |

**因此本报告不含缓存命中率、CPI、每周期指令数等任何 PMU 指标。**
全部结论由「时间 × 字节数 × FLOP」三条口径互推得到。

---

## 二、被测负载定义

| 算子 | 规模 | 每轮搬运 | 算术强度 | 判定 |
|---|---|---|---|---|
| GEMV（decode） | 32 MB 权重 × 1 个向量 | 32 MB | ≈ 0.25 FLOP/字节 | 带宽受限 |
| GEMM（prefill） | n×n×n 方阵，n = 256/384/512 | n² 元素 | n=512 时 ≈ 128 FLOP/字节 | 算力受限 |
| CHASE | 工作集 4 KB ~ 64 MB | — | — | 测各级缓存延迟 |
| STREAM | 8 MB / 128 MB | 读 / 写 / 拷贝 | — | 测顺序带宽 |

---

## 三、测量方法

1. 每个配置跑多次（GEMV 5 次、GEMM 3 次、回归 10 次），**报中位数并给出区间**，不只报最好成绩；
2. 所有变体都打印 `checksum`，用相对误差阈值（1e-4）而非 `==` 判等；
3. 线程只创建一次、每线程内跑 reps 轮——每轮重建线程会把缓存和调度状态清掉，测出来的不是并行度；
4. 每个变体入口写一次 `volatile float g_touch`，防止编译器把跨轮重复调用合并（合并后会出现 83 GB/s 这种不可能值）；
5. `stream` 的读模式用 `uint32_t` 整数累加，避开 `float` 求和的 4 周期加法依赖链（否则测到的是加法延迟，不是带宽）。

## 四、分场景数据

### 4.1 缓存延迟阶梯（`results/secA_cache.txt`）

| 工作集 | ns/次访问 | 对应层级 |
|---|---|---|
| 4 KB | 2.275 | L1 |
| 16 KB | 2.357 | L1 |
| 32 KB | 2.367 | L1（32 KB 装得下） |
| 64 KB | **5.509** | 溢出到 L2 |
| 128 KB | 5.427 | L2 |
| 256 KB | 8.769 | L2 边界 |
| 512 KB | 15.340 | L3 |
| 1 MB | 27.758 | L3 |
| 4 MB | 84.668 | L3 尾部 |
| 8 MB | 100.966 | 溢出到 DRAM（L3 = 6 MB） |
| 64 MB | 138.379 | DRAM |

四段台阶清晰：2.3 ns → 5.4 ns → 15~85 ns → 100~140 ns。

### 4.2 顺序带宽（`results/secB_stream.txt`）

| 模式 | 8 MB | 128 MB |
|---|---|---|
| 读 | 5.19 GB/s | 5.56 GB/s |
| 写 | 6.40 GB/s | 6.24 GB/s |
| 拷贝（读+写都计入） | 20.10 GB/s | 17.81 GB/s |

**口径说明**：读模式是标量累加（每周期 4 字节），理论天花板约 10 GB/s，实测 5.2~5.6 只能当下限用；
拷贝走的是自动向量化的搬运循环，更接近机器真实能力。两者不可直接比较。

### 4.3 decode：GEMV 六变体（`results/secC_gemv.txt`）

| 变体 | 中位 GB/s | 区间 |
|---|---|---|
| 标量 | 1.87 | 1.53 ~ 1.89 |
| AVX2 | 10.56 | 9.58 ~ 10.74 |
| **AVX2×4** | **11.27** | 10.48 ~ 11.46 |
| mt:1 | 8.03 | 3.69 ~ 10.48 |
| mt:2 | 10.06 | 6.11 ~ 12.17 |
| mt:4 | 9.41 | 4.41 ~ 12.95 |

向量化 6.0 倍；多线程**不如单线程**且离散度 2.9 倍。

### 4.4 绑核（`results/secE_affinity.txt`）

| 绑法 | 中位 GB/s | 区间 | 离散度 |
|---|---|---|---|
| **钉 1 颗核** | **10.14** | 9.06 ~ 10.72 | **1.18×** |
| 钉 4 颗核 | 7.72 | 3.19 ~ 11.94 | 3.74× |
| 不钉 | 7.80 | 4.65 ~ 14.99 | 3.22× |

带宽受限的负载，减少并发流比分散到多核更有效；离散度是这里更重要的指标。

### 4.5 prefill：GEMM（`results/secD2_gemm_fixed.txt`，修复越界之后）

| 变体 | n=256 | n=384 | n=512 |
|---|---|---|---|
| 朴素 | 0.79 | 0.88 | 0.59 |
| 分块 64 | 1.37 | 1.34 | 1.27 |
| 2 线程 | 1.68 | 2.72 | 2.34 |
| 4 线程 | 1.99 | 2.56 | **4.38** |

单位 GFLOPS。n=512 时 4 线程最好一次 4.43、最差 4.06。
分块对朴素 2.2 倍；再加线程累计 7.4 倍（n=512）。

### 4.6 优化前后（`results/secF_before_after.txt`）

| 指标 | 优化前 | 优化后 | 倍数 |
|---|---|---|---|
| GEMV 带宽 | 1.87 GB/s（标量单线程） | 11.27 GB/s（AVX2×4） | 6.0× |
| GEMV 单次搬运（32 MB） | 17.95 ms | 2.98 ms | 6.0× |
| GEMM n=512 | 0.59 GFLOPS | 4.38 GFLOPS | 7.4× |

### 4.7 回归与稳定性（`results/secG_regress.txt`）

| 项目 | 结果 |
|---|---|
| checksum（10 次） | 恒为 `-15572.8926`，bit 级一致 |
| 耗时 | 53.87 ~ 73.33 ms（中位 64.56） |
| 带宽 | 9.15 ~ 12.46 GB/s（中位 10.48） |
| 分布形状 | 连续铺开，**无台阶**（无降频/P-state 切换迹象） |
| GEMM 一致性 | naive / block:64 / mt:4 三者 checksum 完全相同 |

## 五、归因与判别

| 现象 | 判别 | 依据 |
|---|---|---|
| 向量化 6 倍 | 带宽受限下仍有收益 | 标量每周期只能搬 4 字节，SIMD 把搬运吞吐吃满 |
| 多线程零收益 | 带宽已饱和 | 单线程已达 11.27 GB/s，4 线程中位降到 9.41 |
| 钉 1 核最快 | 减少并发内存流 | 离散度从 3.7× 收到 1.18× |
| GEMM 加线程有效 | 算力受限 | n=512 算术强度 ≈ 128 FLOP/字节 |
| n=384 mt:4 偏慢 | 线程切分不整齐（96 不是 64 的整数倍） | 每线程最后一块算不满 |

## 六、正确性验证

| 检查 | 结果 | 说明 |
|---|---|---|
| GEMV 变体间 checksum | 相对偏差 4.9e-5 | 在 √N × ε_f32 ≈ 3.5e-4 的正常范围内；根因是求和顺序变化（avx2×4 是 32 条通道、mt 是分段部分和） |
| GEMV 同变体多次 | bit 级一致 | 无竞态、无未初始化内存 |
| GEMM 变体间 checksum | 完全相同 | 分块与按行切线程都不改变「每个 C[i][j] 沿 k 累加」的顺序 |
| GEMM 修复越界后 | 三个尺寸全一致 | 见 README 的 bug 复盘 |

判等不能用 `==`，要用相对误差阈值；阈值要按「数据量 × 机器精度」估，不能拍脑袋。

---

## 七、边界声明

1. 全部数字来自 **x86 + AVX2**。RK3588（4×A76 + 4×A55、NEON、L3 更小）只能借鉴方向，不能照抄倍数。
2. 这台机器**没有大小核**，只能验证「绑核本身值多少」，验证不了「大小核怎么选」。
3. **没有 vPMU**，所以没有任何缓存命中率 / CPI 数字；瓶颈判断全部靠时间口径互推。
4. `stream` 的读模式受标量累加限制（5.2~5.6 GB/s 是下限，不是机器上限），
   与拷贝模式（17.8~20.1 GB/s）不可直接比较。
5. 多线程在虚拟机上的离散度很大（最差到最好的比值常超过 3），
   报告里所有结论都用**中位数**下的判断，不用最好成绩。
