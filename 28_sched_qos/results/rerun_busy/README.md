# 这是一次「宿主较忙」时的重跑，用来说明边界

同一份代码（`code/sched23.c` + `code/run23.sh`），同一天（2026-11-22 11:04–11:11）在**同一台虚拟机**上重跑一遍，
结果与 `results/sec*.txt`（正文数字的来源）对不上，而且**排序反了**：

| 配置 | 正文那一批（宿主较安静） | 这一次（宿主较忙） |
|---|---|---|
| 什么都不做 | 27.81 ms / 36.0 token/s | 24.46 ms |
| 只绑核（cpu3） | 25.53 ms / 39.2 token/s | 25.24 ms |
| 只做 cpuset 隔离 | **20.01 ms / 50.0 token/s（最快）** | **26.84 ms（最慢）** |
| 隔离 + 实时优先级 | 31.49 ms（最慢） | 29.73 ms |

「隔离」从最快变成最慢，差了 7 ms，而正文的结论恰好建立在 3~7 ms 这一档差距上。

这不是代码坏了，也不是正文造假，而是这台机器的固有边界：vCPU 由宿主时间片切出来，
当宿主上有别的负载时，几十毫秒级的对比会被背景噪声整个淹掉。

所以：

- 正文的结论只用**同一窗口内多次重复、方向一致**的那些项（配额、权重、饥饿、策略对比这几组的方向在两次运行里都一致）
- 横向只差百分之几的项，本仓库一律不当作结论
- 想真正比较 5% 的差异，要么上物理机，要么把每档重复 10 次以上取分布

文件命名 `rA…rK` 对应 `run23.sh` 的段落，字段与 `../sec*.txt` 完全一致。
