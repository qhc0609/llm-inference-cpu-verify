# 大模型持续推理的「性能 · 功耗 · 温度」联合测试报告

被测对象：一个按 decode 阶段特征写的最小推理循环（32 MB 权重，每 token 全量读一遍）。
测量时间：2026-11-22。测量人：本系列作者。所有原始输出见 `results/`。

---

## 一、环境能力清单（决定全篇口径）

| 项目 | 内容 |
|---|---|
| 内核 | Linux 6.8.0-149-generic（Ubuntu 24.04.5 LTS） |
| 处理器 | Intel Core i5-7300HQ @ 2.50 GHz |
| 拓扑 | 4 vCPU，单处理器组，KVM 虚拟机 |
| 内存 | 16 GB |
| 编译器 | gcc 13.3.0 |

**能读到的接口**

| 接口 | 能给什么 |
|---|---|
| `/proc/cpuinfo` | 静态标称频率 2496.005 MHz（不随负载变，不能当实际频率） |
| `/proc/pressure/cpu` | PSI：有任务想跑但没 CPU 的时间占比（avg10） |
| `getrusage(RUSAGE_THREAD)` | 线程级 CPU 时间（μs），不含被换出等待 |
| cgroup v2 | `cpu.max`（配额）、`cpu.stat`（usage_usec） |

**读不到的接口**

| 接口 | 期望 | 实测 |
|---|---|---|
| `/sys/devices/system/cpu/cpu0/cpufreq` | `scaling_cur_freq` / `scaling_governor` | 目录不存在 |
| `/sys/class/thermal/thermal_zone*` | `temp` / `trip_point_*` | 0 个 |
| `/sys/class/thermal/cooling_device*` | 降温手段 | 4 个 type=Processor，未绑定任何 zone |
| `/sys/class/powercap` | RAPL `energy_uj` | 空 |
| MSR `0x198` | 当前 P-state 比例 | 四核全读出 0 |

**结论：本报告不含任何频率、温度、功耗的直接测量值。**

## 二、被测负载定义

| 项目 | 值 |
|---|---|
| 权重规模 | 32 MB（8 388 608 个 float） |
| 每 token 读取字节 | 32 MB（全量，无复用） |
| 每 token 乘加次数 | 约 838 万次 |
| 算术强度 | 约 **0.25 FLOP/字节** |
| 判定 | 远低于 CPU 的算力带宽比（20~50），**带宽受限** |

这个负载对应真实 7B FP16 模型 decode 阶段的特征（14 GB 权重 / 70 亿乘加 ≈ 0.25 FLOP/字节），
只是把规模缩小到能在一台机器上反复跑。

## 三、测量方法

1. **逐 token 采样**：每生成一个 token 前后各读一次 `getrusage(RUSAGE_THREAD)`，两次相减得该 token 的 CPU 时间；
2. **窗口结算**：每 10 秒（短测 5 秒）结算一个窗口，窗口内所有 token 的 CPU 时间排序取 **p10**；
3. **为什么取 p10**：干扰（被抢 CPU、缓存被换掉、补页表）只会让 CPU 时间**变长**，
   所以「最快的那 10%」代表无干扰时的真实速度；平均值把这堆干扰全算进来了；
4. **为什么 p10 能当频率代理**：`p10 ∝ 1/f`，频率掉 30%，同样的活就要多花 43% 的 CPU 时间；
5. **对照组**：用 cgroup `cpu.max` 削减时间份额（不改频率、不改电压），
   验证「吞吐下降但 p10 不变」这种组合确实可以发生。

## 四、分场景数据

### 4.1 单线程 240 秒（`results/secC2_p10.txt`）

24 个窗口。吞吐 34.8~50.5 token/s（中位 46.3）；p10 15957~16964 μs（中位 16100）。
**p10 全程无单调上升**；吞吐的抖动与 PSI 同步（最低点 34.8 出现在 PSI=5.71 的窗口）。

### 4.2 四线程 180 秒（`results/secD2_p10.txt`）

18 个窗口。吞吐 45.6~136.8 token/s（中位 103.7）；p10 中位 **15953 μs**，与单线程的 16100 只差 0.9%。
PSI 常年 12~36（单线程是 0~6）。

### 4.3 并行效率

1 线程 46.3 → 4 线程 103.7 token/s，**2.24 倍**（理论 4 倍）。
原因是四个线程抢同一份内存带宽，不是频率下降。

### 4.4 间歇运行（`results/secF_burst.txt`）

40 秒开 / 20 秒停，四轮：

| 轮次 | token/s | 每 token CPU 时间（μs） |
|---|---|---|
| 1 | 92.4 | 34247 |
| 2 | 99.3 | 32624 |
| 3 | 86.5 | 36244 |
| 4 | **74.8** | **40680** |

两个数一起变差（−19% / +19%），**是真正的劣化**，但四轮里 PSI 也在逐轮上升，
且本机无温度传感器——**无法归因到温度**。

### 4.5 cgroup 配额对照（`results/secG_quota.txt`）

| 配额 | 写入 cpu.max | token/s | 每 token CPU 时间 | 相对吞吐 |
|---|---|---|---|---|
| 100% | `100000 100000` | 47.2 | 20.09 ms | 1.00 |
| 50% | `50000 100000` | 26.1 | 18.18 ms | 0.55 |
| 25% | `25000 100000` | **14.0** | **17.25 ms** | 0.30 |

吞吐按配额近似线性下降；每 token 的 CPU 时间**不升反降**（与降频的预测方向相反）。
这组数据验证了核心方法：**「时间变少」和「算得变慢」是完全不同的两件事**。

### 4.6 恢复曲线（`results/secE_recover.txt`）

满载后单线程探针 120 秒，15 个窗口：均值 182.7 Mops/s，区间 154.5~227.3。
前 9 窗口均值 169.0，后 6 窗口均值 **203.2**——后段反而更高，**无持续衰减**。

## 五、归因与判别

| 观察到的现象 | 判别 | 依据 |
|---|---|---|
| 单线程吞吐大幅抖动（34.8~50.5） | 被抢 CPU | p10 不变（±6%），PSI 与低谷同步 |
| 四线程吞吐抖动 3 倍（45.6~136.8） | 被抢 CPU | p10 中位与单线程相同，PSI 12~36 |
| 4 核只快 2.24 倍 | 带宽受限 | 算术强度 0.25，加核加不了带宽 |
| 间歇第 4 轮 −19% | **真劣化，但归因未定** | 吞吐与 p10 一起坏；无温度接口可证 |
| 配额腰斩后吞吐腰斩 | 时间份额减少 | p10 不升反降 |

## 六、边界声明

1. **本报告未测量频率、温度、功耗。** 这台机器没有 cpufreq、thermal zone、powercap，
   MSR 与 PMU 也不可用。「未观察到降频」是被环境决定的，**不可外推为「真机不会降频」**。
2. **间歇组的劣化没有归因。** 观察到了逐轮变差，但缺少温度证据，只写「观察到」不写「因为热」。
3. **短测与长测的绝对值不可横向比较。** 40 秒窗口含冷启动，每 token 的 CPU 时间会偏高
   （配额组 100% 是 20.1 ms，240 秒长跑是 16.1 ms）；只能各自内部比趋势。
4. **换到真机要补三处**：
   - 频率：`scaling_cur_freq` 或 `turbostat`；
   - 温度：`thermal_zone*/temp` 或 `/sys/class/hwmon`；
   - 功耗：Intel RAPL（`powercap/intel-rapl`）或板载 PMIC / INA 电流计。
   方法（吞吐 + p10 双指标）不变，证据链从两条变三条。
